# 敏感数据脱敏

采集结果常含个人数据：邮箱、手机号、身份证、银行卡、IP、API Key。
一旦进了导出文件（尤其交给他人或上传云存储），就构成**数据泄漏**。

项目已有 `security-report`，但那是**声明层**——它说明「会访问什么」，
不处理「导出里有什么」。这个插件补上后者。

## 它做什么

导出前扫描每条记录，按**字段名 + 值模式**双重判定，把命中内容脱敏，
并返回逐类命中统计（便于核对脱敏是否真的生效）。

```json
{
  "items": [{"name": "张三", "phone": "138*****678",
             "note": "打 139*****111"}],
  "counts": {"field": 1, "phone_cn": 2},
  "total_hits": 3,
  "reversible": false,
  "summary": "脱敏完成：1 条记录，共 3 处命中（field×1, phone_cn×2）"
}
```

## 支持的模式

| 类型 | 说明 |
|---|---|
| `id_card` | 18 位身份证（含末位 X） |
| `bank_card` | 16-19 位卡号（容忍空格/连字符分组） |
| `email` | 邮箱 |
| `phone_cn` | 中国大陆手机号 |
| `ipv4` | IPv4 |
| `api_key` | `sk-` / `ghp_` / `xoxb-` / `AKIA` 等常见前缀的长串 |

## 两种模式

**默认不可逆**（掩码）：`13812345678` → `138*****678`。适合大多数交付。

**可逆**（配 `secret`）：输出 `h:<16位>`（HMAC-SHA256）。
同样的原值 + 同样的 key 得到同样的哈希，可用于**关联分析**而不暴露原值。

> ⚠️ `secret` 经 payload 传入，插件**不读密钥文件、不写盘**（`permissions: []`）。
> 不要在配置里明文写长期密钥——用环境的注入机制。

## 白名单：为什么必须有

业务标识常常长得像 PII：订单号 `13812345678` 恰好 11 位数字，会被
`phone_cn` 规则误伤，破坏可追溯性。

`FIELD_ALLOWLIST = ("order_id", "serial", "sku", "gid", "trace_id")` 里的
字段**完全跳过所有规则**（连值匹配也不做）。

> 这里踩过一个坑：早先白名单只挡「字段名含敏感词」那一条，值的模式匹配
> 照做，于是 `order_id` 仍被当成手机号脱敏。已修并加了断言。

## 配置

```yaml
plugins:
  mask-sensitive:
    secret: ""            # 留空 = 不可逆掩码；给值 = HMAC 可关联
    keep: 3               # 掩码保留首尾字符数
    patterns: true        # 是否做值的模式匹配（关掉只按字段名判定）
```

## 边界

- 纯函数、无 IO，`permissions: []`；
- **只处理字符串与标量**——嵌套对象原样保留（避免误改结构）；
- 不做 OCR/PDF 内的文本脱敏（那是另一层的事）。
