# diff-report · 变更对比报告

把两次采集结果对比成「新增 / 删除 / 修改」三类差异。

## 为什么需要

增量采集最常见的需求是「这次比上次变了什么」。用户想知道的不是「一共 500 条」，
而是「有 3 条新增、1 条改价、2 条下架」。

## 用法

```yaml
transformers:
  - name: diff-report
    options:
      key_field: 商品ID     # 用哪个字段当稳定键（默认 key）
      ignore: [抓取时间, etag]   # 每次都会变的字段不参与比较
```

## 三条判据

| 判据 | 为什么 |
|---|---|
| 按**稳定键**建索引，跳过无键条目 | 没有键就无法判断"同一个东西"，宁可不算也不猜 |
| `ignore` 里的字段不参与比较 | `fetched_at` / `etag` 每次都变，纳入比较会让所有条目都报"修改" |
| **只报哪些字段变了**，不整条回传 | 报告要能一眼读完 |

## 输出

```json
{
  "added": ["k3"],
  "removed": ["k1"],
  "changed": [{"key": "k2", "fields": ["价格"]}],
  "counts": {"previous": 2, "current": 2, "added": 1, "removed": 1, "changed": 1},
  "summary": "对比完成：新增 1、删除 1、修改 1（前 2 → 现 2）"
}
```

## 权限与数据去向

**零权限**。隔离子进程、纯函数、不读文件、不联网、无第三方依赖。
