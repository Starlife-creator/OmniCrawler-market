# validate-items · 导出前质量校验

在导出前拦下「空字段 / 重复键 / 明显异常」的条目。

## 为什么需要

采集的失败常常是**静默的**：页面改版后标题选择器失效，于是所有条目的 `title`
都是空串 —— 采集「成功」了 500 条，实际全是废数据。等到用户打开导出文件才发现，
已经跑了几十分钟。

这个插件在导出前做一遍质量检查，把问题**当场报出来**。

## 三类问题

| 类型 | 含义 | 典型原因 |
|---|---|---|
| `missing` | 必填字段为空 | 选择器失效 / 页面改版 |
| `duplicates` | 稳定键重复 | 分页或去重逻辑有问题 |
| `suspicious` | 值明显异常（疑似整段 HTML / 超长）| 抓错了元素 |

## 两条判据（容易写错的）

1. **`0` 与 `False` 不算空** —— 它们是合法数据。只有 `None` / `""` / `[]` / `{}` 算空。
2. **只报告，不修改数据** —— 是否丢弃由调用方按 `fail_on` 决定。
   校验器偷偷改数据，会让"我到底交付了什么"变得不可追溯。

## 权限与数据去向

**零权限**。隔离子进程、纯函数、不读文件、不联网、无第三方依赖。
