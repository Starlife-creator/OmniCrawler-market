# 文本相似度与变更检测

`diff-report` 只做**字段级**比较（`price` 从 199 变 299）。但长文本的真实问题是
另一类：

* 正文改了三个字 → 整篇被判「完全变了」，下游收到无意义告警；
* 页面只换了广告位/推荐位 → 抓下来的正文其实没变，却被当新内容入库。

需要的是「**相似度**」，不是「相等/不等」。

## 三档判定

| 判定 | 含义 | 建议动作 |
|---|---|---|
| `identical` | 相同（含仅换行/缩进差异） | 跳过，省钱 |
| `minor` | 相似但未达阈值 | 记为「微调」，不告警 |
| `changed` | 低于阈值 | 当真变更处理 |

```json
{"ratio": 0.875, "verdict": "minor", "changed": false,
 "before_len": 10, "after_len": 10,
 "summary": "相似度 0.875 -> minor"}
```

## 为什么折叠空白

抓下来的正文常因排版换行不同而「看起来变了」。`_normalize()` 把连续空白
折成单空格，消除这类噪声，**但不改词序与标点**。

实测：`"第一段。\n\n第二段。"` 与 `"第一段。 第二段。"` → `ratio=1.0000`，
判 `identical`。这正是期望行为。

## 为什么不用 `quick_ratio()`

标准库的 `quick_ratio()` 在大文本上更快，但对**顺序调换**不敏感，会高估
相似度。正文场景宁可慢一点也要准，所以用 `ratio()`。

## 配置

```yaml
plugins:
  text-similarity:
    identical: 0.995    # >= 此值视为相同
    minor: 0.85         # >= 此值视为微调
```

阈值应按语料调：短文本（标题）适合更高阈值，长正文可放低。

## 两个操作

| 操作 | 载荷 | 用途 |
|---|---|---|
| `processor.similarity` | `{before, after}` | 比一对 |
| `processor.similarity-pairs` | `{pairs: [{key, before, after}]}` | 批量比，返回分档计数 |

批量示例输出：

```
共 3 对：相同 1、微调 0、实质变更 2
```

## 边界

* **只用标准库**（`difflib`），零第三方依赖；
* 纯函数、无 IO，`permissions: []`；
* 不做语义相似度（那是 embedding 的事，代价完全不同）。
