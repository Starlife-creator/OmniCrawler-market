# text-similarity · 文本相似度与变更检测

判断两次采集的内容「是不是**实质**变了」。

## 为什么需要

`diff-report` 只做字段级比较（`price` 从 199 变 299）。但真实场景更常见的是
**长文本的细微变化**：

- 正文改三个字 → 整篇被判「完全变了」，下游收到无意义告警；
- 页面只换了广告位/推荐位 → 正文其实没变，却被当新内容入库。

需要的是「**相似度**」而不是「相等/不等」。

## 三档判定

| 判定 | 含义 | 典型动作 |
|---|---|---|
| `identical` | 完全相同（>= 0.995）| 跳过（省钱）|
| `minor` | 相似但未超阈值（>= 0.85）| 记录为「微调」，不告警 |
| `changed` | 低于阈值 | 当真变更处理 |

阈值可配（`identical` / `minor`）。

## 两个刻意的选择

1. **先折叠空白再比**：抓下来的正文常因排版换行不同而"看起来变了"，实际一致。
   折叠连续空白消除这类噪声，但**不改变词序与标点**。
2. **用 `ratio()` 而不是 `quick_ratio()`**：后者在大文本上更快，但对「顺序调换」
   不敏感，会高估相似度。正文场景宁可慢一点也要准。

## 权限与数据去向

**零权限**。隔离子进程、纯函数、不读文件、不联网、只用标准库 `difflib`。
