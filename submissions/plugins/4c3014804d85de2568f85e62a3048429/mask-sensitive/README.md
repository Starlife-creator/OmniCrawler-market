# mask-sensitive · 敏感数据脱敏

导出前把 PII / 凭据替换成不可逆掩码，避免「采集成功但导出了别人的隐私」。

## 为什么需要

采集结果常含邮箱、手机号、身份证、银行卡、IP、API Key。一旦进了导出文件
（尤其交给他人或上传云存储），就构成**数据泄漏**。项目已有的 `security-report`
是**声明层**（说明会访问什么），不处理「导出里有什么」—— 这个插件补上后者。

## 三条设计取舍

| 取舍 | 理由 |
|---|---|
| **默认不可逆**（掩码/哈希）| 简单、安全，适合大多数交付场景；需要回溯用 `secret` + HMAC |
| **字段名 + 模式双重判定** | 只看字段名会漏（`note` 里塞了手机号）；只看模式会误伤（订单号长得像手机号）|
| **报告而不只替换** | 返回每个字段命中多少次，便于核对脱敏是否生效 |

`FIELD_ALLOWLIST`（`order_id` / `serial` / `sku` / `gid` / `trace_id`）里的字段
即使命中模式也不脱敏 —— 它们是业务标识，不是个人身份。

## 权限与数据去向

**零权限**。隔离子进程、纯函数、不读密钥文件、不写盘（密钥经 payload 传入）。

## 兼容与许可

- OmniCrawler `>=0.7.0` · MIT

## 已知限制

- 模式匹配是**启发式**，不是分类器：漏检与误伤都可能发生，报告里的计数就是给你核对的。
- 只处理字符串值，不递归下探嵌套对象。
